Fast mode and standard speed keep separate caches, so after a toggle the next
request cannot use what the other speed cached. The first time you turn fast
mode on in a conversation, the next request reads the whole history uncached,
billed at fast mode rates. Turning it on at the start of a session therefore
costs less than turning it on deep into a long one.

Each later toggle reads uncached whatever the speed you switch to does not have
cached. Speed changes Claude Code makes on its own count as toggles too, such as
falling back to standard speed after a rate limit and returning to fast mode
later.

If your current model does not support fast mode, enabling it also switches the
model, and that switch starts a fresh cache on its own.
