Tool definitions live in the system prompt layer, so what matters is whether a
server's tools are in the prefix at all.

**Deferred by tool search,** the default on supported models: a server
connecting, disconnecting, or changing its tool list appends new content and
disturbs nothing already cached.

**Loaded into the prefix:** adding a definition rebuilds everything behind it,
and so does removing one on purpose.
Tools load into the prefix when tool search is unavailable or disabled, for a
server or tool marked `alwaysLoad`, and for definitions kept upfront by
threshold-based loading.

In that second case a connected server that adds tools through a dynamic tool
update rebuilds the cache without you doing anything. A server that drops out
on its own, such as a stdio server whose process exits, keeps the cache, and so
does a remote server reconnecting automatically, unless a request sent during
the reconnect adds the `WaitForMcpServers` tool, which costs one rebuild.
Editing the MCP config itself changes nothing until a restart.
